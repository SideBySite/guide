## ページ数と、00を追加する理由

前の設計は疑問64ページ。詳細名鑑40〜50人程度と両監督を加えても、およそ106〜116ページです。初観戦の入口にはなる一方、ユーザーが求める派生疑問や、その場で目を移す面白さを掘り切るには薄い設計でした。過去の野球ガイドは記事ファイル377本でした。

今回の00-A〜Hでは、場面・役割・関心から各35〜45候補を掘ります。00-Iで既存64問と合わせて重複を除き、**疑問200〜280ページ程度＋人物カードを別枠**として検討します。L1は45〜65程度、残りは「読んだ後に次に湧く疑問」にします。数合わせで同義のページを量産しません。

最初に読む10〜15問程度、今日役立つ★、気になったときの詳説を分けます。厚いガイドでも初見の画面を質問だらけにしない構成です。目標の件数を下回る場合は、品質を守った上で足りない視点と理由を明示し、発掘工程で補います。

## いま進める順序

1. **02・03は、そのまま継続。** どの配布版を使っていても、送付済みの依頼を取り消したり送り直したりしません。初版では02＝FC東京全体・03＝柏全体、直前の改訂版では02＝編集仕様・03＝FC東京候補選定でした。番号だけで判断せず、完了した実ファイルを00-Jで対応付けます。
2. **00-A〜Hと01R-A〜Eは独立して着手可。** 互いに別フォルダへ保存し、02/03のファイルを上書きしません。
3. 00-A〜Hの後に00-I。01R-A〜Eの後に01R-F。
4. **00-I・01R-F・進行中02/03が完了したら00-J。** 新しい土台と最終ツリーを採用し、既存担当と衝突しない追加EX-*プロンプトを自動分割して保存します。
5. 固定の執筆担当04〜30は各開始条件で進められます。00-Jが作る追加担当と合わせ、採用した全質問を執筆・逸話・推敲・事実確認へ回します。
6. 31で全採用IDを動的にサイトへ組み込み、32〜34で共有事実とチーム・戦略の整合、35で全件への到達・スマホ表示・公開を確認します。36は必要な場合の公式メンバー更新です。

**00-Jの実行後は、このフォルダ内のruntime/README.mdが追加プロンプトの入口になります。** これはまだ生成前です。00-Jが完了するまで、追加記事が執筆済み・ガイドが完成したとは扱いません。

## 01を「1からやり直す」の扱い

新稿は `foundation-v2/` へ作ります。初めに疑問の順序と答え方を設計し、foundation-v2/drafts/へ1問1ファイルで新しい草稿を書き、その後に初版の使える根拠を照合します。語尾や見出しだけの修正で済ませません。

初版01のPLAN・facts・basics、02/03のdocs・teams・statusはそのまま保管します。新土台の採用・互換性の調整は先行担当の完了後に00-Jで行います。作り直しのために02/03を途中で止めません。

## 過去版から守る型

- 記事は1問1ファイル。執筆は1チャット6〜10本前後、詳細名鑑は最大5人。
- L1は500〜1000字、L2は250〜600字が目安。短くするために具体性を削りません。
- 「15歳くらいへ、淡々と筋道立ててやさしく」「〜なのだ／〜というわけだ／〜だ」。専門語は初出でかっこ説明。
- ひとことで→しくみ→歴史・由来→おもしろエピソード→今日の試合で見るなら。存在する意味がある節を使います。
- 名鑑は育成年代・プロ・直近1年・直近試合それぞれの経歴、競技内外のエピソード、印象的な試合、実績、論点まで全項目。
- 逸話は日英5検索以上・候補3以上・5観点採点。数字やしくみの言い換えで埋めません。
- 太字・黄色いマーカー・補足・関連記事を使用。本文と一致しない画像を入れません。
- 1記事／1人ごとに保存・コミットし、担当外を編集しません。

## 完了の確認

「コピーした」だけでは完了ではありません。担当PRがmainへ反映され、実際の原稿とstatusがあることを確認して次へ進みます。サイト実装・公開の指示は本文の調査をしたふりをせず、全採用記事と人物カードに到達できることを確認します。

このフォルダへの今回の追加は**制作の指示書**です。00の発掘、01Rの再制作、追加ページの執筆そのものを実行した状態ではありません。
