# 口調・記事の型（過去の野球ガイドから引き継ぐ）
- 読み手はサッカーをまったく知らない大人。球場の待ち時間にスマホで1〜2分ずつ読む。15歳くらいの人に説明するつもりで、やさしく、ただし具体性を落とさない。
- 語り手は落ち着いていて感情をあまり出さず、淡々と筋道立ててやさしく説明する。文末は「〜なのだ」「〜というわけだ」「〜だ」を基本にする。読み手には「あなた」と呼びかけてよい。すべての文を機械的に「なのだ」にそろえない。
- 数字・選手名・場面・なぜそうなるかの理屈を入れ、なんとなくでごまかさない。たとえは身近なものを使い、最後にサッカーへ戻す。キャラクター名・作品名・決めぜりふを本文に入れない。
- 専門語は初めて出すとき必ずかっこで言い換える。昔の選手・チーム・賞も一言説明。1文40字前後、1段落3文まで。箇条書きは並列の項目だけ。
- 記事は1問1ファイル。L1は500〜1000字、派生L2は250〜600字が目安。理解に必要なら長くしてよい。見出しは「ひとことで」「しくみ」「歴史・由来」（あれば）「おもしろエピソード」（条件を満たす話があれば）「今日の試合で見るなら」。今日の欄は必須で、どの選手・どの場面・どこに注目するかを具体的に書く。
- 太字は初出用語・数字・選手名に1段落1〜2か所。==黄色いマーカー==は要点に1記事3〜6か所。補足は引用形式「> 」、関連リンクはIDでつなぐ。詳細名鑑にも同じ口調と装飾を使う。
- エピソードは、誰が／どんな場面で／何をしてどうなったかがそろう話。数字・成績だけ、しくみの言い換え、直近の結果報告で埋めない。面白さは①子どもでも笑える・驚ける②今日の見え方が変わる③なぜ？が解ける、の順。下品な話や締めのダジャレは使わない。見つからなければ無理に作らない。

事実と予想を分け、公開資料を自分で確認し、根拠URLと基準日を残す。既存人物・記事のIDやslugを勝手に変えず、初版の有効な資料を保存する。担当範囲の保存・PR・自分のPRのmainへのマージまで実行してよい。他のPRや進行中のファイルは操作しない。

# ページ数と品質
現行の固定分は疑問64記事。人物カードは別枠。今回の目的ではこれだけを上限にしない。
00の候補と固定64問を統合し、目安として疑問200〜280（L1は45〜65、残りは意味のあるL2）、別に出場候補40〜50人前後と両監督の詳細を見込む。ただし数合わせを優先しない。同じ答え・同じ見る場所の言い換えは統合し、適切な数が下回るなら不足領域と理由を明記して、候補の追加発掘をこの担当で補う。根拠のない細分化で200に合わせない。
最初の試合前に読む10〜15問程度、当日押しやすい★、もっと気になったときの通常記事を分ける。全体の厚みと、初見で迷わない入口を両立させる。

# 編集の手順
1. 全候補の採否と理由を1件ずつ記録。意味が重なるものは代表を選び、元候補IDを全て残す。
2. 1〜7の各カテゴリで、L1→それを読んで浮かぶL2（通常2〜5個）、さらに別記事へのrelatedで2階層に整える。3階層を増やして深くしない。
3. 初心者が見る場面を、試合前／再開／攻撃／守備／ボール外／交代／休憩／終了に照らし、役割もGK/DF/MF/FW/控え/監督で確認する。質問が用語辞典だけ、または玄人の戦術用語だけになっていないか点検。
4. FC東京と柏、主役と支える人、仕組みと逸話、長い大会と今日1試合、会場生活のバランスを点検。説明内容や観察行動が独立する場合だけページを分ける。
5. 薄い部分を追加調査して新たな候補を提案し、出典入口と必要な確認を添える。選手名や今日の特徴を未確認で断定しない。
6. 正式IDはまだ確定せず、候補IDと既存64IDを対応させる。既存64IDの削除・改名を指示しない。不要と思う既存記事は理由付きで統合候補とするが、実行中の担当を止めない。
