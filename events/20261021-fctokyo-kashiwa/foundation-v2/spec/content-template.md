# 新土台の記事仕様（01R-F確定）

## 目的と単位

**1問＝1本文ファイル**。最初の観戦で出会う疑問を一つだけ選び、短い答え、理由と具体例、今日見る場所の順で理解をつなぐ。旧版の長いFAQを切り分けただけの原稿や、目次・見出しだけのファイルは記事完成と数えない。

- **L1（入口の問い）**：原則500〜1000字。単独で読んでも答えがわかる。
- **L2（派生の問い）**：原則250〜600字。L1から派生する一点を深め、L1の再掲にしない。
- 説明・図の正確さを保つためなら目安を超えてよい。その場合は長くなった理由を監査で確認する。出典リスト・図仕様・front matterだけで分量を満たしたことにはしない。
- **固定64問のIDを保持**。01R-B/C/D/Eの `01R-X-Qxx` は暫定原稿IDであり、正式IDではない。00-Jの照合で重複と派生関係を決めるまでIDを置換しない。

## 記事ファイルの型

以下は新規原稿の見本。実際の本文では括弧内の制作指示を残さず、自分の言葉で書く。既存のdraft front matterを一律書換えするための指示ではない。

~~~markdown
---
draft_id: 01R-X-Q01
title: 観客が本当に聞く一つの疑問？
category: basics
level: L1
article_id_status: provisional
baseline_ids: [1-01]
related_draft_ids: [01R-X-Q02]
as_of: 2026-10-21試合開始前
checked_at: 2026-10-21T12:49:00+09:00
sources:
  - https://www.jfa.jp/laws/soccer/2026_27/
---
~~~

本文見出しの基礎形は **「ひとことで」→「しくみ」→「今日の試合で見るなら」**。中間に「歴史・由来」「おもしろエピソード」を加える場合は、根拠があるときだけ。図の仕様・出典・関連リンクは必要に応じて別記する。**「今日の試合で見るなら」は全記事で必須**だ。

## スマホで読める語り口

1. 読み手はサッカー未経験の大人。15歳くらいにも理解できる言葉で、1〜2分ずつ読む。**1文40字前後、1段落は3文まで**が目安だ。すべて同じ文末にするのではなく、淡々と因果関係を説明し、「〜なのだ」「〜というわけだ」「〜だ」を基本とする。
2. 専門語は**初登場時にかっこで説明**する。例：オフサイド（相手のゴール前での待ち伏せを制限する決まり）。GK、VAR、ACL、FKなどの略語も初出で言い換える。過去の選手、チーム、賞も「いつの誰か」を一言添える。
3. 公式の**数字**、固有の**選手名**、目に見える**場面**、そうなる**理由**を入れる。ただしルールの例なら「もし〜なら」として、起きていないことを事実にしない。身近なたとえを使ったら、必ずサッカーの場面へ戻す。キャラクター名・作品名・決めぜりふを読者本文に書かない。
4. 太字 `**…**` は初出用語・数字・選手名の強調に使い、原則**1段落1〜2か所**。黄色マーカー `==…==` は核となる理解に**1記事3〜6か所**。補足は `> ` の引用形式。箇条書きは並列項目のみ。関連は**記事ID**で管理し、最終的な公開リンク変換は31で行う。
5. 「今日」の節は、**選手／場面／場所／観察する差**を結ぶ。例：「柏の古賀太陽が出るなら、FC東京が右側から攻めた時、ボールの後ろで誰のコースをふさぐか」。出場候補と先発発表、観客席から見える動きと本人の意図を混同しない。席種・応援側は未指定なので一律に決めつけない。
6. 写真は、文章の直近にある対象そのものを写し、**Wikimedia Commonsの作者・ライセンス・画像URL**が確認できる場合だけ。別選手・別会場の代替写真は不可。なくてもよい。説明図・表は条文と矛盾しない正確な位置・数で作る。図制作メモを完成した図として公開しない。

## エピソードの合格線

「おもしろエピソード」は成績欄ではない。**誰が／いつ・どこでどんな場面で／何をしてどうなったか**がそろい、話を知らない人が情景を思い浮かべられる話だけ採る。優先順位は①子どもも笑える・驚ける、②今日の見え方が変わる、③なぜそうなるかが腑に落ちる、の順だ。

数字だけ、しくみの言い直し、直近試合のスコア報告を逸話に置かない。過去の実話でも、当時のクラブ名・用語を説明する。発言なら本人の確認できる発言と文脈を示し、心情を創作しない。下品な話や締めのダジャレは禁止。合格する話がなければ**見出しごと置かない**。

選定する担当では、日英の検索を合わせて5回以上、候補3件以上から、**驚き／今日への接続／なぜを解く／情景／根拠の確かさ**をそれぞれ5点で評価し、採否を記録する。根拠のない話は点数にかかわらず見送る。この評価は旧 `scripts/build_prompts.py` の `epi_prompt` をサッカー向けに引き継ぐものだ。

## 事実の書き方と作業の順序

- **確認済み**（公式による日程・制度・記録）、**取材報道**（媒体・掲載日）、**予想**（未発表の起用等）、**観察仮説**（読者への着目点）を区別する。
- **対象日・対象大会・発表日・確認時刻（JST）・成績の集計日**を別々に持つ。2026年春の百年構想リーグと2026/27 J1は別大会だ。規則はJFA/IFABの**2026/27適用版**とJリーグの採否告知の両方を読む。
- 試合後の結果を試合前の予想として逆輸入しない。選手・監督・背番号・役割・当日入場案内は当該日の公式確認を優先する。未確認なら確認不能と明記する。先発未発表時の人物例は「出場すれば」と書く。
- 自分の担当記事の**執筆→逸話調査→推敲→個別確認**は順番に実施し、1問ずつ保存・コミット。他担当の共有質問表・割当表・候補表・旧記事を上書きしない。土台の完成は独立した記事や人物調査の開始条件としない。
